# v1.0.6 · 防篡改加密版

**发布日期**：2026-05-18

这一版给受控库的每一份输出 PDF 都套上一层 AES-256 加密 + 权限锁定，**WPS / Adobe Acrobat / Foxit 等编辑器无法删章、无法改字、无法加注释**。同时输出文件名自动加 `【受控】` 后缀，肉眼一秒识别受控件。

---

## 🎯 这一版要解决的痛点

旧版（v1.0.5）的受控章是矢量画到 PDF 内容流里的——好看，但 WPS 这类完整 PDF 编辑器照样能轻松删掉印章、改图纸文字、加注释。**等于受控库的"权威性"在末端被绕过了**。

这一版把"挡得住编辑器"作为硬指标。

---

|---|---|---|

| WPS / Adobe / Foxit 改图纸文字 | ❌ 轻松 | ✅ 拒绝 |
| 加注释 / 拆页 / 重组 | ❌ 轻松 | ✅ 拒绝 |

| 持有 owner 密码的人解锁 | — | ⚠ 可解锁 |

## ✨ 新增功能

- **AES-256 加密**：PDF 2.0 (R=6) 标准加密；流 / 字符串 / 文件均用 AESv3。
- **【受控】后缀**：`M.M.1.0033.pdf` → `M.M.1.0033【受控】.pdf`，一眼可辨。
- **SHA256 防伪短码**：状态栏和批量列表显示输出文件的 SHA256 前 8 位（如 `a1b2c3d4`），作为审计参考。
- **系统只读位**：输出文件自动 `attrib +R`，避免无意覆写。
- **已盖章检测升级**：识别 `【受控】` + 历史 `[8hex]` 两种格式，批量模式可自动跳过。

---

## 🔄 行为变更

- 单文件输出名不再加 `_stamped` 后缀。
- 重命名时先剥离 `_stamped` / `[8hex]` / `【受控】`，再加新的 `【受控】`，防止 `xxx_stamped [abcd]【受控】.pdf` 这种鬼名字。
- 元数据 `Producer` → `Controlled-PDF-Studio v1.0.6`。

## 🚀 升级指引

### 普通用户

1. 直接装新版（v1.0.6 安装版可以直接装在 v1.0.5 之上）。
2. **历史用 v1.0.5 加过章的 PDF 不会自动重新加密**——这些文件依旧是可编辑的，**重要件建议批量重跑一次 v1.0.6**。
3. 批量重跑：把历史的 `_stamped/` 目录作为输入，输出到新的 `_stamped_v106/` 目录即可（已勾"跳过已加章"则需要先取消勾选，因为旧文件文件名就是 `xxx_stamped.pdf`，需要重处理）。

### 开发者

1. 拉最新代码：`git pull origin main`
2. 安装依赖：`npm install && npm run setup:qpdf`
3. 构建：`npm run dist`

## ⚠️ Owner 密码

Owner 密码写死在 `electron/handlers/pdf.ts` 里。**不要在公开文档 / 公司公告 / Wiki 里写明密码**，否则等于没加密。

建议密码归口管理：
- 公司密码管理器（1Password / Bitwarden）记一份
- 只发给 IT + 受控库管理员（2~3 人）
- 普通工程师不需要知道

---

## 🛠 已知局限

- **网上 PDF 解锁工具能绕过权限位** —— PDF 规范层面的固有问题，不是 qpdf 的缺陷。这一层主要挡"无心 / 顺手"的编辑，而不是恶意破解。
- **没有数字签名** —— 如需"任何篡改后审计可见"，需要叠加 PKCS#7 签名（计划项，v1.1.0 考虑）。
