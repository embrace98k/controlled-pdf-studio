# v1.0.7 · 单文件手动选导出位置

**发布日期**：2026-05-19

这一版把单文件模式的"应用并导出"流程改成 Windows 标准"保存为"对话框，不再强制写到 `<源目录>\_stamped\` 子文件夹。同时修了一个 v1.0.6 引入的文件名误碰撞 bug。

---

## ✨ 新增功能

### 单文件导出改为手动选位置

| | v1.0.6 | v1.0.7 |
|---|---|---|
| 点击"应用并导出" | 自动写到 `<源目录>\_stamped\xxx_stamped.pdf` | **弹 Windows 标准"保存为"对话框** |
| 默认保存目录 | 强制 `_stamped\` 子文件夹 | **源 PDF 同目录**（可改） |
| 默认文件名 | `<原名>_stamped.pdf` | **`<原名>【受控】.pdf`**（可改） |
| 想换位置 | 改不了，得手动拷 | 直接在对话框里点导航 |
| 取消导出 | — | 状态栏显示"已取消"，不报错 |

**典型场景**：以前给同事的图纸都得手动从 `_stamped/` 拷出来；现在可以直接选保存到桌面、邮件附件目录或网盘文件夹。

### 文件名边界场景

不管用户在保存对话框里把名字改成什么，主进程都会规整：

| 用户输入名 | 实际产出 |
|---|---|
| `M.M.1.0033【受控】.pdf`（默认）| `M.M.1.0033【受控】.pdf` |
| `M.M.1.0033.pdf`（去掉【受控】） | `M.M.1.0033【受控】.pdf`（自动补） |
| `M.M.1.0033_stamped.pdf`（老后缀） | `M.M.1.0033【受控】.pdf`（剥离 + 补） |
| `M.M.1.0033 [a1b2c3d4].pdf`（更老） | `M.M.1.0033【受控】.pdf`（剥离 + 补） |
| 同名文件已存在 | `M.M.1.0033【受控】 (1).pdf` |

## 🐛 修复

- **`buildFinalPath` 自身碰撞误判**：v1.0.6 时如果用户的保存路径已经带 `【受控】`，主进程会把 qpdf 输出的临时文件当作"已存在的目标文件"，错误地追加 `(1)` 后缀。  
  现在跳过对 `originalOutput` 自身的 `existsSync` 检查，结果一致正确。

---

## 🔧 维护性改进

- **`docs/generate-intro-pdf.cjs` 改为从 `package.json` 自动读版本号** —— 以后升版本不用再到 PDF 生成脚本里手动改 4 处字符串。
- **新增 `.cursor/rules/auto-bump-patch-version.mdc`** —— 项目约定持久化，AI 协作时改完代码自动升 patch 版本，写 CHANGELOG，写 release notes。

## 🚀 升级指引

### 普通用户

1. 直接装新版（覆盖 v1.0.6）。
2. **历史用 v1.0.6 加过章的 PDF 不受影响**——加密机制没变，只是导出 UX 改了。

### 开发者

1. 拉最新代码：`git pull origin main`
2. 走 PDF 生成脚本：`node docs/generate-intro-pdf.cjs`（如需重生成手册）
3. 构建：`npm run dist`
